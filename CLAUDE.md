## What `namzy` is

A family of **four parallel, equivalent implementations** of the same name-generator algorithm, one per language, each shipped as its own publishable package in a sibling subfolder:

- `namzy-ts/` — TypeScript
- `namzy-py/` — Python
- `namzy-cpp/` — C++ (Qt5-compatible)
- `namzy-rs/` — Rust

The four are siblings, not a monorepo with shared code. Each must stand alone as an installable/publishable package for its language ecosystem.

## Algorithm contract (shared across all four)

Output is **always one fused token** — short (≤12 chars), memorable, distinct. Two short stems concatenated, lightly rotated, capitalized.

Stems live in `data/` as 12 hand-curated discipline packs (cities, rivers, colors, adjectives, nouns, verbs, names, trees, birds, gems, weather, myth). Every stem is filtered to **≤2 syllables and ≤7 characters**. Each implementation bundles a unified deduplicated list (~950 stems) emitted by `scripts/generate_data.py`.

Rotations are **syllable-based**: ~150 safe rewrites stored in `data/rotations.txt`. The bulk are open-CV swaps (`pa→po`, `ti→ty`, `ki→ky`, `mo→ma` …) — they preserve syllable shape so the result is still pronounceable. A handful of unambiguous letter swaps (`k↔q`, `c↔k`, `ph↔f`, `x↔ks`) round out the set. There is **no class-wide single-letter rotation** — `ss` cannot become `zz`.

Bad-seam list in `data/badseams.txt` rejects candidates whose junction window (±2 chars around the seam) contains a doubled-identical-vowel sound (`aa`, `ee`, `ii`, `oo`, `uu`, `yy`, `iy`, `yi`).

Steps:
1. Pick **two stems** at random.
2. Concatenate. Validate: length ≤ 12, no triple identical letter anywhere, no bad-seam at the junction. Retry up to 8 times.
3. Find every position where a rotation rule matches; apply **exactly one** at a randomly chosen match.
4. Capitalize the first letter.

Seeded by current timestamp or caller-supplied integer. ASCII only.

`scripts/generate_data.py` is the source of truth — it writes both `data/*.txt` and per-language wordlist files (`namzy-ts/src/wordlist.ts`, `namzy-py/src/namzy/_wordlist.py`, `namzy-rs/src/wordlist.rs`, `namzy-cpp/src/wordlist.{h,cpp}`). Re-run after editing stem packs.

The spec explicitly states: *"Not every implementation must yield identical results."* Keep the code simple.

## Working in this repo

- When implementing a language port, work inside its subfolder and follow that ecosystem's conventions (`package.json` + tsc/tsup for TS, `pyproject.toml` + uv for Python, CMake/qmake for the Qt5-compatible C++ build, `Cargo.toml` for Rust).
- The top-level `README.md` should describe the shared contract above and link to each subpackage; per-language READMEs cover install/usage for that ecosystem.
- Resist adding shared tooling, a monorepo manager, or a build orchestrator — the spec wants four independent packages, not a coordinated build.
