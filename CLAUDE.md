## What `namzy` is

A family of **four parallel, equivalent implementations** of the same name-generator algorithm, one per language, each shipped as its own publishable package in a sibling subfolder:

- `namzy-ts/` — TypeScript
- `namzy-py/` — Python
- `namzy-cpp/` — C++ (Qt5-compatible)
- `namzy-rs/` — Rust

The four are siblings, not a monorepo with shared code. Each must stand alone as an installable/publishable package for its language ecosystem.

## Algorithm contract (shared across all four)

Output is **always one fused token** that looks like a single word but is two words spliced together and mangled. There is **no** shape option.

1. Pick two words from the vocabulary (one geo + one common offline, or two from the online API). Lowercase both.
2. Junction cleanup at the seam, up to two passes:
   - if `last(word1) == first(word2)` → drop `first(word2)`
   - else if both are vowels (`a e i o u y`) → drop `first(word2)`
3. Concatenate without separator.
4. Consonant rotation (case-preserving, per letter): `c→q · f→v · k→c · q→k · s→z · z→s · v→f · w→u`.
5. Capitalize first letter only.

Seeded by current timestamp or caller-supplied integer. Vocabulary is basic `A–Za–z` only.

Two modes required:
- **Self-contained** — bundled wordlist, no network.
- **Online** — public no-auth API; falls back to bundled on failure.

The spec explicitly states: *"Not every implementation must yield identical results."* Keep the code simple.

## Working in this repo

- When implementing a language port, work inside its subfolder and follow that ecosystem's conventions (`package.json` + tsc/tsup for TS, `pyproject.toml` + uv for Python, CMake/qmake for the Qt5-compatible C++ build, `Cargo.toml` for Rust).
- The top-level `README.md` should describe the shared contract above and link to each subpackage; per-language READMEs cover install/usage for that ecosystem.
- Resist adding shared tooling, a monorepo manager, or a build orchestrator — the spec wants four independent packages, not a coordinated build.
