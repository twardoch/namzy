Revise the algorithm fully. Ultrathink, ultrathoroughly. Understand that we want to have names that are compact, memorable, but very unique. We should work as follows: 

## Stems

1. In the `data/` folder generate 'stem packs'. 
2. Each stem pack should contain 200 words.  
3. Each stem pack should be from a different realm, area, discipline: 
- city
- river
- color name
- positively charged adjective
- positively charged noun
- positively charged verb
- first name
4. All stems should be short, compact, portable across languages, recognizable across cultures, and easy to combine with other stems 

## Combining

Each implementation should hold its own list of stems. We can unify them into 1 list (we only keep them separate in 'data' folder for management purposes). 

The algorithm form a compound by combining ANY 2 stems: can be river+city or or city+river or verb+verb, whatever. 

## Rotation

We should creatively think of rotation rules so that each consonant or vowel can be rotated to something else. We should store the rotation rules also in the ./data/ folder. 

On the input compound, we only perform 1 or 2 rotations on randomly selected letters to produce the final name. No more. 

## Capitalization

The first letter of the name should be capitalized. 

## Output

The output should be number of names corresponding to the input number (default: 1). 

## Testing

Write tests that into tests/output/ produce a list of 10,000 names. Benchmark each implementation and compare the performance.
